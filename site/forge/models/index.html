Models

This page lists every model the anvil tracks, the harness that runs it, and the effort it runs at. A model is the trained system that does the thinking. A harness is the app that lets a model work on your files. A riff is one command that starts a model in its harness, with your flags already set. The anvil's riff is a bash function, shown below, and you can build your own in any shell. For the plans behind these models, see Balancing the Anvil.

The riff bill of rights

A riff is named after a musical riff, a short phrase you play again and again. Each one bakes in a harness, your model of choice, and any arguments you want. For example, you might run something like riff opus when the work in front of you calls for Opus. Whatever it launches, a riff owes you these:

  • Each model is a subcommand of one riff command, such as riff opus.
  • A riff never launches in your home directory or in /. It moves to a sandbox instead, so you can riff from anywhere.
  • A riff always returns you to the directory where you started.
  • A riff runs in the foreground and returns the exit code to your shell.
  • A riff passes extra arguments straight through to the CLI.
The smallest riff, one harness
# riff opus, riff sonnet: one vendor, one effort, nothing else
riff() { claude --model "${1}" --effort high "${@:2}"; }
A more advanced riff setup in bash 4+
# riff <model> [args...]: one launcher, one model per subcommand
riff() {
  # the shared engine every model calls: run the CLI (blocking), then
  # restore your working directory when the CLI exits, via a trap
  _riff_shell() {
    local bin="${1}" origin="${PWD}" sandbox="${AI_SHELL_SANDBOX:-${HOME}/sandbox}"; shift
    # never turn an agent loose in your home dir (ssh keys, dotfiles, creds) or at /; sandbox it
    # defaults to ~/sandbox, created on first use; override with AI_SHELL_SANDBOX
    if [[ "${PWD}" == "${HOME}" || "${PWD}" == "/" ]]; then
      mkdir -p "${sandbox}" || return
      cd "${sandbox}" || return
    fi

    # ~~~~~ make it yours here: customizations, tab title, color, whatever ~~~~~

    trap 'trap - RETURN; cd "${origin}"' RETURN  # back to where you started when the CLI exits
    "${bin}" "${@}"                              # keep last so a Ctrl-C still runs the cleanup
  }

  # each model is just a thin declaration: a client, a model, and any flags you want
  # defining a _riff_cmd_* function is all it takes to register it
  _riff_cmd_fable()  { _riff_shell claude --model fable  --effort high  "${@}"; }
  _riff_cmd_opus()   { _riff_shell claude --model opus   --effort high  "${@}"; }
  _riff_cmd_sonnet() { _riff_shell claude --model sonnet --effort high  "${@}"; }
  _riff_cmd_astra()  { _riff_shell codex  --model gpt-6.2-astra --config "model_reasoning_effort='low'"  "${@}"; }
  _riff_cmd_sol()    { _riff_shell codex  --model gpt-6.2-sol --config "model_reasoning_effort='low'"    "${@}"; }
  _riff_cmd_terra()  { _riff_shell codex  --model gpt-6.1-terra --config "model_reasoning_effort='low'"  "${@}"; }
  _riff_cmd_luna()   { _riff_shell codex  --model gpt-6-luna  --config "model_reasoning_effort='medium'" "${@}"; }
  _riff_cmd_lite()   { _riff_shell junie  --model junie-lite "${@}"; }

  # Tab completion: bash sets COMP_LINE only when it calls riff as a completer
  if [[ -n "${COMP_LINE:-}" ]]; then
    COMPREPLY=()
    [[ "${COMP_CWORD}" -eq 1 ]] || return 0  # complete the model name only
    mapfile -t COMPREPLY < <(compgen -W "$(compgen -A function _riff_cmd_ | sed 's/^_riff_cmd_//')" -- "${COMP_WORDS[COMP_CWORD]}")
    return 0
  fi

  # dispatch: riff opus -> _riff_cmd_opus, with any extra args passed along
  local cmd="${1:-}"
  shift
  if declare -F "_riff_cmd_${cmd}" >/dev/null; then
    "_riff_cmd_${cmd}" "${@}"
  else
    printf 'usage: riff <model> [args...] (press Tab to list models)\n' >&2
    return 2
  fi
}
complete -F riff riff
